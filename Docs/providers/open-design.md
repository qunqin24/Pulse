# Open Design

Profiled provider: [`Sources/Pulse/Providers/Profiled/OpenDesignUsageService.swift`](../../Sources/Pulse/Providers/Profiled/OpenDesignUsageService.swift). User setup: [../setup/open-design.md](../setup/open-design.md).

- **Credential:** `.localLogin`. The login Open Design's runtime (`vela`, "AMR") saved in `~/.amr/config.json`: `profiles.prod.controlKey`, and `profiles.prod.apiUrl` when set (default `https://amr-api.open-design.ai`). A profile with `pendingLogin` is not a login. Only `prod` is read — the profile Open Design uses unless `OPEN_DESIGN_AMR_PROFILE` / `VELA_PROFILE` say otherwise — and `AMR_HOME` is not followed. The key is sent only to an `https` address on `open-design.ai` with no user info in it; any other saved address is treated as no login.
- **Route:** per refresh, with `Authorization: Bearer <controlKey>`; redirects refused, 3xx/401/403 = the saved login expired.
  1. `GET /api/v1/workspaces` → `{ items: [{ workspaceId, workspaceType, isDefault, … }] }`. The owner's default personal workspace is read, else the first personal one; none → "no plan".
  2. `GET /api/v1/workspaces/<id>/billing/funding-check?workspaceId=<id>` (no model) → `WorkspaceBillingPreflight`: `{ balanceUsd, codingPlan: { tier, windows: [{ policyId, durationSeconds, resetMode, usedCredits, remainingCredits, limitCredits, windowStart, resetsAt }] } }`. This is the Coding Plan — OpenDesign Go's 5-hour and 7-day pools, the 7-day pool on Plus, Pro and Max — and what Open Design's own billing panel draws (`coding-plan-usage-model.ts`). A refused login here is final.
  3. Only when step 2 failed for another reason or had no window: `GET /api/v1/workspaces/<id>/billing/snapshot?workspaceId=<id>` → `WorkspaceBillingSnapshot`: `{ billing: { planId }, wallet: { balanceUsd }, designPlanWindows: [{ kind: "5h" | "7d", windowStart, resetsAt, remainingCredits, limitCredits }] }`. A wallet-only answer from step 2 stands if this one fails.
  Credits are integers written as strings, and a pool can be far past 2^53; the share is taken in `Double`, which is exact enough for a ring.
- **Windows:** Coding Plan windows are `openDesign.codingPlan.<policyId>`, named by `durationSeconds` as Open Design names them — 5 h `.fiveHour`, a day `.daily`, 7 days `.weekly`, 28–31 days `.monthly`; any other length is left off rather than guessed. `usedCredits / limitCredits`, reset at `resetsAt`, exhausted when nothing remains. Snapshot windows are `openDesign.fiveHour` / `openDesign.weekly`, `(limit − remaining) / limit`. A limit of zero or a missing figure is left off. The plan is the tier or `planId` capitalised (`Go`, `Plus`, `Pro`, `Max`); the wallet is a USD balance.
- **OpenDesign Go API keys are not a route.** Open Design's API accepts only the account's control key for billing and account reads and rejects runtime keys (`specs/current/amr-wallet-balance-display.md`; a workspace API key "cannot stand in for an account login"), so a Go subscriber has to sign in to the Open Design app once on this Mac.
- **Left out, deliberately:** team workspaces (one account per Mac login; a team seat is not the reader's own plan); plan model credits, which have no window and whose limit the snapshot does not state; per-model coverage (`modelId`), which answers whether one send can start, not how much is left.
- **Evidence:** second-hand. The shapes come from Open Design's own source (`nexu-io/open-design`, read 2026-11-11): the `WorkspaceBillingPreflight` and `WorkspaceBillingSnapshot` contracts in `packages/contracts`, the daemon's billing (`vela-billing.ts`) and workspace directory reads, the web client's Coding Plan model and the end-to-end billing fixture. The funding-check path is the daemon's own; the snapshot path is the one its test double for the `vela` CLI maps to. No live account has been read. Fixtures: `Tests/PulseTests/Fixtures/opendesign-*.json`.
