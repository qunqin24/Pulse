# Open Design

Profiled provider: [`Sources/Pulse/Providers/Profiled/OpenDesignUsageService.swift`](../../Sources/Pulse/Providers/Profiled/OpenDesignUsageService.swift). User setup: [../setup/open-design.md](../setup/open-design.md).

- **Credential:** `.localLogin`. The login Open Design's runtime (`vela`, "AMR") saved in `~/.amr/config.json`: `profiles.prod.controlKey`, and `profiles.prod.apiUrl` when set (default `https://amr-api.open-design.ai`). A profile with `pendingLogin` is not a login. Only `prod` is read — the profile Open Design uses unless `OPEN_DESIGN_AMR_PROFILE` / `VELA_PROFILE` say otherwise — and `AMR_HOME` is not followed. The key is sent only to an `https` address on `open-design.ai` with no user info in it; any other saved address is treated as no login.
- **Route:** per refresh, with `Authorization: Bearer <controlKey>`; redirects refused, 3xx/401/403 = the saved login expired.
  1. `GET /api/v1/workspaces` → `{ items: [{ workspaceId, workspaceType, isDefault, … }] }`. The owner's default personal workspace is read, else the first personal one; none → "no plan".
  2. The plan's windows, from the first route that has any; every request also names the workspace in `x-vela-workspace-id`, as the console does, and a refused login on any of them is final:
     - `GET /api/v1/workspaces/<id>/billing/coding-plan-usage` → `{ eligible, tier, windows: [{ policyId, durationSeconds, remainingCredits, limitCredits, resetsAt, … }] }`. What the open-design.ai console's usage panel reads (its published bundle, `cloud/assets/app-*.js`).
     - `GET …/billing/funding-check` → `WorkspaceBillingPreflight`: the same plan object under `codingPlan`, with `balanceUsd` beside it. What the desktop daemon reads (`vela-billing.ts`).
     - `GET …/billing/snapshot` → `WorkspaceBillingSnapshot`: `{ billing: { planId }, wallet: { balanceUsd }, designPlanWindows: [{ kind: "5h" | "7d", windowStart, resetsAt, remainingCredits, limitCredits }] }`. The console reads it too.
     An answer with figures but no window is kept and shown only if no route has a window.
  Credits are integers written as strings, and a pool can be far past 2^53; the share is taken in `Double`, which is exact enough for a ring. `usedCredits` when given, else `limit − remaining`.
- **Windows:** Coding Plan windows are `openDesign.codingPlan.<policyId>`, named by `durationSeconds` as Open Design names them — 5 h `.fiveHour`, a day `.daily`, 7 days `.weekly`, 28–31 days `.monthly`; any other length is left off rather than guessed. `usedCredits / limitCredits`, reset at `resetsAt`, exhausted when nothing remains. Snapshot windows are `openDesign.fiveHour` / `openDesign.weekly`, `(limit − remaining) / limit`. A limit of zero or a missing figure is left off. The plan is the tier or `planId` capitalised (`Go`, `Plus`, `Pro`, `Max`); the wallet is a USD balance.
- **OpenDesign Go API keys are not a route.** Open Design's API accepts the account login — the control key, or the console's browser session (`credentials: "include"` against `amr-api.open-design.ai`) — for account and billing reads, and rejects runtime keys (`specs/current/amr-wallet-balance-display.md`, `amr-wallet-balance-vela-handoff.md`: "Runtime keys remain rejected"; a workspace API key "cannot stand in for an account login"). Neither client has a usage read that takes an API key. Not tried with a real key. A Go subscriber has to sign in to the Open Design app once on this Mac. The console's browser session would be a second route, but its cookie names are not in the bundle and were not read.
- **Left out, deliberately:** team workspaces (one account per Mac login; a team seat is not the reader's own plan); plan model credits, which have no window and whose limit the snapshot does not state; per-model coverage (`modelId`), which answers whether one send can start, not how much is left.
- **Evidence:** second-hand. The shapes come from Open Design's own source (`nexu-io/open-design`, read 2026-11-11): the `WorkspaceBillingPreflight` and `WorkspaceBillingSnapshot` contracts in `packages/contracts`, the daemon's billing (`vela-billing.ts`) and workspace directory reads, the web client's Coding Plan model and the end-to-end billing fixture, and the open-design.ai console's published bundle (read 2026-11-11), which calls `coding-plan-usage` and `snapshot` directly. No live account has been read. Fixtures: `Tests/PulseTests/Fixtures/opendesign-*.json`.
