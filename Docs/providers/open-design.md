# Open Design

Profiled provider: [`Sources/Pulse/Providers/Profiled/OpenDesignUsageService.swift`](../../Sources/Pulse/Providers/Profiled/OpenDesignUsageService.swift). User setup: [../setup/open-design.md](../setup/open-design.md).

- **Credential:** `.sessionCookie(host: "open-design.ai")`, kept to `__Secure-better-auth.session_token` (required) and the rest of the `__Secure-better-auth.` prefix — the console's sign-in, which CodexBar names as the one cookie its billing reads need. Sent as `Cookie` to `amr-api.open-design.ai` with the console's `Origin`/`Referer`. **Fallback, when no session is held or the session is refused:** the desktop app's login in `~/.amr/config.json`: `profiles.prod.controlKey`, and `profiles.prod.apiUrl` when set (default `https://amr-api.open-design.ai`). A profile with `pendingLogin` is not a login. Only `prod` is read — the profile Open Design uses unless `OPEN_DESIGN_AMR_PROFILE` / `VELA_PROFILE` say otherwise — and `AMR_HOME` is not followed. That key is sent only to an `https` address on `open-design.ai` with no user info in it; any other saved address is treated as no login. Neither present → "read a browser session".
- **Route:** per refresh; redirects refused.
  1. `GET /api/v1/workspaces` → `{ items: [{ workspaceId, workspaceType, isDefault, … }] }`. The owner's default personal workspace is read, else the first personal one; none → "no plan". A 3xx/401/403 here is the credential refused: the session expired, or the app's login did.
  2. The plan's windows, from the first route that has any, each naming the workspace in `x-vela-workspace-id` as the console does:
     - `GET /api/v1/workspaces/<id>/billing/coding-plan-usage` → `{ eligible, tier, windows: [{ policyId, durationSeconds, usedCredits, remainingCredits, limitCredits, resetsAt }] }`. What the console's usage panel reads (its published bundle) and what CodexBar reads, with the session. First for the session; second for the app's login, with which it is unverified (`dsh-opendesign-corouter` deliberately sends it cookies only).
     - `GET …/billing/funding-check` → `WorkspaceBillingPreflight`: the same plan object under `codingPlan`, beside `balanceUsd`. What the desktop daemon reads with the control key (`vela-billing.ts`; `dsh-opendesign-go` reads it through `vela`). First for the app's login; not asked with the session.
     - `GET …/billing/snapshot` → `WorkspaceBillingSnapshot`: `{ billing: { planId }, wallet: { balanceUsd }, designPlanWindows: [{ kind: "5h" | "7d", … remainingCredits, limitCredits }] }`. Last: `dsh-opendesign-go` and `dsh-opendesign-corouter` report it answering 403 since 2026-10-19.
     A 401/403 from a billing route rules out that route only — step 1 already showed the credential is good. Every billing route refusing → "no plan". An answer with figures but no window is kept and shown only if no route has a window.
  Credits are integers written as strings, and a pool can be far past 2^53; the share is taken in `Double`, which is exact enough for a ring. `usedCredits` when given, else `limit − remaining`. For scale, `dsh-opendesign-go` measured Go's limits at 50,000 credits per 5 hours and 150,000 per 7 days.
- **Windows:** Coding Plan windows are `openDesign.codingPlan.<policyId>`, named by `durationSeconds` as Open Design names them — 5 h `.fiveHour`, a day `.daily`, 7 days `.weekly`, 28–31 days `.monthly`; any other length is left off rather than guessed. `usedCredits / limitCredits`, reset at `resetsAt`, exhausted when nothing remains. Snapshot windows are `openDesign.fiveHour` / `openDesign.weekly`, `(limit − remaining) / limit`. A limit of zero or a missing figure is left off. The plan is the tier or `planId` capitalised (`Go`, `Plus`, `Pro`, `Max`); the wallet is a USD balance.
- **OpenDesign Go API keys are not a route.** Open Design's API accepts the account login — the control key or the console's browser session — for account and billing reads, and rejects runtime keys (`specs/current/amr-wallet-balance-display.md`, `amr-wallet-balance-vela-handoff.md`: "Runtime keys remain rejected"; a workspace API key "cannot stand in for an account login"). CodexBar's notes say the same ("Inference API keys cannot authenticate these billing endpoints"), and the DSH plugins use the runtime key only for models and inference. Not tried with a real key here. A Go subscriber who only uses the key signs in at open-design.ai in a browser instead.
- **Left out, deliberately:** team workspaces (one account per Mac login; a team seat is not the reader's own plan); plan model credits, which have no window and whose limit the snapshot does not state; per-model coverage (`modelId`), which answers whether one send can start, not how much is left.
- **Evidence:** second-hand. Open Design's own code (`nexu-io/open-design`, read 2026-11-11: the `WorkspaceBillingPreflight` and `WorkspaceBillingSnapshot` contracts, the daemon's billing and workspace reads, the web client's Coding Plan model) and the open-design.ai console's published bundle; and other projects that read it: CodexBar's OpenDesign plugin (`docs/opendesign.md`, session route, fixtures from a sanitized contract, no live account), `EliteOtaku/dsh-opendesign-go` (`docs/quota.md`, measured Go's window sizes through `vela`) and `KouzakiUmi/dsh-opendesign-corouter` (`docs/quota-evidence.md`). No live account has been read here. Fixtures: `Tests/PulseTests/Fixtures/opendesign-*.json`.
